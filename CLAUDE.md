
Backend assistant rules (FastAPI + PostgreSQL ticketing portal)

When told "Build Bnn":
1. Read Backend_Build_Guide_v2.md by line range only (find headings with grep): section 3 (Context Pack), section 4 (gate), the Part Bnn section, the Appendix A parts it needs, and the Appendix R sections it names. Read the files the part lists under Reads.
2. Create or modify only the files the part lists. Write complete files.
3. Run the gate and fix failures until it passes. If it still fails after two attempts with the same cause, stop and report.
4. Report FILES CREATED, FILES MODIFIED, ASSUMPTIONS (maximum 5), the self-check list answered yes or no, and the gate result. Keep the report short.
5. Stop. Do not start another part, unless given a range ("Build Bnn to Bmm"): then build the parts in order, run the full gate after each, report each part, and stop at the first gate that cannot be fixed.

Hard rules: contract first (reply CONTRACT_GAP: and stop if Appendix A lacks something); rules first (reply RULE_GAP: and stop if Appendix R lacks something); never invent endpoints, fields, enum values, error codes, or rules. No code comments, no docstrings, no print, no TODO, no type: ignore. Services never commit; routers are thin; all permission and visibility logic lives in app/policy; time only through the injected Clock. Only the allowed packages. Synchronous SQLAlchemy 2.0, real PostgreSQL in tests, no Redis or Celery. Public endpoints never return HTTP 401. A ticket the caller may not see returns the same 404 as a missing ticket. Confidential tickets must never leak through any list, count, search, notification, audit entry, email, or error message.

Environment
- Run from this folder in Git Bash: `source .venv/Scripts/activate`.
- Docker Postgres is on host port 5433 (a local Windows PostgreSQL 17 service owns 5432). Start with `docker compose up -d db mailpit`.
- Gate: `ruff check . && ruff format --check . && mypy app && mypy tests scripts alembic/env.py alembic/versions && pytest -q -p no:warnings && alembic upgrade head && alembic check && python scripts/check_contract.py --full` (`--full` from B23 on). Release gate (B26) runs pytest with `--cov=app`, then `coverage report --fail-under=85` and `coverage report --include="app/policy/*,app/services/sla/*" --fail-under=95`. `tests/perf` skips itself under `--cov`; run `pytest tests/perf` separately without coverage.

Established conventions (B01 to B04)
- Enum columns use `enum_type(EnumClass, "name")` from app/models/base.py so lowercase values are stored.
- Migrations: `alembic revision --autogenerate --rev-id bNN_short_name -m "..."`, then delete the `# ###` comment lines, fix circular FKs, and add data or triggers by hand.
- Tests: `db` fixture (savepoint, rolled back), `committed_db` (real commits; cleanup keeps policy_versions version 1 and truncates IMMUTABLE_TABLES), `clock` FrozenClock at 2026-10-27T04:30:00Z, `client` overrides get_db and get_clock. Factories in tests/factories.py are plain functions.
- `ticket_events` is immutable (DB trigger). `to_ist` uses a fixed +05:30 offset (no tzdata on Windows).
- Small non-A.2 enums live next to their models: EmailTokenPurpose, Theme (identity.py); CloseReason, TicketEventKind (ticket.py); TimerKind (sla.py); EmailStatus (notification.py).
